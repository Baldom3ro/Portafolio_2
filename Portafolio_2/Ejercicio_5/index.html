Estrategia Network-First con Fallback a IndexedDB

Consumo de API REST remota con fetch. Al recibir el JSON, se respalda automáticamente en IndexedDB. Si la red falla o se pierde la conexión, la interfaz recupera y renderiza el último estado almacenado localmente de forma transparente.

📐 Flujo de Ejecución de la Estrategia Network-First con Fallback 

async function fetchWithIndexedDbFallback(endpoint) {
  // 1. Intentar obtener datos frescos desde la RED
  try {
    if (simularOffline) throw new Error('Simulación de red caída');
    
    const response = await fetch(endpoint, { cache: 'no-cache' });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();

    // 2. Éxito en Red: Guardar copia fresca en IndexedDB
    await apiCacheDB.saveApiResponse(endpoint, data);
    renderInterface(data, 'NETWORK');
  } 
  // 3. Fallo en Red (Sin internet o servidor caído): Activar FALLBACK
  catch (networkError) {
    console.warn('Red no disponible. Leyendo respaldo desde IndexedDB...');
    const localBackup = await apiCacheDB.getCachedResponse(endpoint);

    if (localBackup) {
      // 4. Renderizar automáticamente los datos cacheados
      renderInterface(localBackup.payload, 'INDEXEDDB_FALLBACK', localBackup.timestamp);
    } else {
      renderEmptyState('Sin conexión y sin respaldo local previo.');
    }
  }
}
